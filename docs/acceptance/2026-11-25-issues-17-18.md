# Admin UI acceptance: seven.io webhook registration (#17) and messages held by Meta (#18) (2026-11-25)

Build under test: `npm pack` of this branch (commits `feat(seven)`, `feat(whatsapp)`, `fix(admin)`), installed from the tarball into an isolated host.

## Host

- Strapi 5.63.0 and `@strapi/plugin-users-permissions` 5.63.0, SQLite, loopback port 1491, `admin.autoOpen: false`, plugin `publicUrl` `https://cms.example.test`.
- Providers in live mode against the local fake server (`scripts/cluster/fake-providers.cjs`, loopback port 1492), which now keeps seven.io hooks per server like a real account. `NODE_OPTIONS=-r block-egress.cjs` (only loopback sockets) for the build, the seed and the server; the browser context aborted every non-loopback request. The server log had no blocked egress attempt.
- Secrets generated with `crypto.randomBytes` into a mode-600 `.env`; the admin was registered through `POST /admin/register-admin` with a generated password. `.env`, the admin credentials and the database were deleted after the run.
- Synthetic fixtures (seed through the plugin services): a Meta account, two seven.io accounts (one fresh, one whose webhook URL already had a hand-made form hook at the fake seven.io), an approved WhatsApp and SMS template `order_shipped`, four contacts `+49 151 2345678 1…4`, and messages: delivered, held (`held_for_quality_assessment`), held (`paused`), held then released (`sent`, `delivered`), held then dropped (`failed` 132015, SMS fallback sent).
