# Several processes on one PostgreSQL database (2026-11-11)

Build under test: `strapi-plugin-magic-messagegate` 1.0.0 packed from `feat/messagegate` (commit 97901eb), installed into an isolated Strapi 5.61.0 host.

## Setup

- PostgreSQL 16 on 127.0.0.1:5440, fresh database `mg_cluster`.
- 8 Strapi processes (`strapi start`, `NODE_ENV=production`) on ports 1491–1498, two groups of four, all on the same database. The first process starts alone and creates the schema; the other seven start afterwards.
- A non-sticky round-robin TCP balancer on 1480 sends every new connection to the next process.
- Fake WhatsApp (Meta), seven.io, Telegram and Twilio servers on 1481, control API on 1482. Outbound network blocked by a preload; only loopback connections are possible.
- Synthetic numbers `+49155501xxxxx`, synthetic accounts and secrets. Nothing real is contacted.
- Content API calls use a full-access Strapi API token; webhooks are signed with the account's app secret and sent to randomly chosen processes.

The run found two harness issues, fixed in this branch: the egress preload path was not quoted in `NODE_OPTIONS` (checkouts in folders with spaces), and the final lease query used `await` on the wrong expression. Settings changes reach every process within about 3 seconds; the proof waits that long after changing them.

## Defect found by the 1.0 run

Strapi 5.61 registers the API-token strategy as `content-api-token`. The Content API only recognised `api-token`, so the per-token rate limit fell back to the client IP and the new token-only rule refused real tokens. Fixed in 97901eb with a regression test.

## Reproduce

The harness lives in the acceptance host folder (`cluster/start.sh`, `cluster/balancer.cjs`, `cluster/fake.cjs`, `cluster/proof.mjs`): create an empty PostgreSQL database, set `DATABASE_CLIENT=postgres` and `DATABASE_URL`, run `cluster/start.sh`, then `N=500 node cluster/proof.mjs`.
