## Upgrade path

The host first ran the published 1.0 code with the 1.0 fixture script (4 accounts, 7 templates, 32 contacts, 33 messages), then the 1.1 tarball on the same SQLite database. Start-up added the new tables and contact columns, the 1.0 settings loaded unchanged (chain `whatsapp → telegram → sms` kept, new keys with defaults), and the 1.1 fixture script added an RCS account, RCS and Telegram templates with buttons, HLR checks and nine inbound messages (text, button replies, a photo, a PDF, a voice note, a location, an SMS answer and an RCS suggested reply) through signed provider webhooks. All three files were downloaded, checked and stored in the media library.

## Security review of the new surfaces

| Surface                                   | Controls                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/magic-messagegate/files/:token` | 128-bit HMAC over id and expiry, expiry checked twice (token and row), one plain `404` for every failure, rate limit per IP in the database, `attachment` + `nosniff` + sandbox CSP, local paths confined to `public/uploads`, remote files only redirected                     |
| Attachment URLs                           | `https` only, port 443, no credentials, no local, private, loopback, link-local, CGNAT or IPv4-mapped private hosts; never fetched by MessageGate                                                                                                                               |
| Inbound media downloads                   | provider ids validated, URLs only on the provider's hosts (Meta CDN domains, `api.telegram.org`, the account's `api.twilio.com` media path; Twilio redirect followed once without credentials), size cap while streaming, type allow-list, magic bytes, EXIF removal, scan hook |
| Inbound webhooks                          | unchanged signature checks; inbound rows unique per provider message id, so retries and parallel processes store and announce a message once; text and captions sealed                                                                                                          |
| Inbound Content API                       | separate controller and token permissions, API token required, per-token rate limit, ids validated                                                                                                                                                                              |
| Outgoing webhook                          | `https` and public DNS answers checked when saving and before each delivery, no redirects, 10 s timeout, HMAC-SHA256 with timestamp, payloads without phone numbers or text. Residual risk: DNS can change between the check and the request (documented)                       |
| Sandbox                                   | refused outside `providers.mode: 'sandbox'` (`SANDBOX_ONLY`); a warning is logged at start in sandbox mode                                                                                                                                                                      |
| Logs                                      | codes and ids only; no phone numbers, text, file names or tokens                                                                                                                                                                                                                |
